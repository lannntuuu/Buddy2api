# Buddy2api v2.2.0

发布日期：2026-08-27

新增 **Trae SOLO** 通道（`traesolo`）。默认打开五家：WorkBuddy、QClaw、千问办公、TraeWork、Trae SOLO。
协议实现参考 [trae2api-web](https://github.com/connectedGraph/trae2api-web)（Go 版 TRAE SOLO 反代），本版本为 Python 原生 provider。

## 功能

- 通道 id `traesolo`，显示名 `Trae SOLO`。未设置 `CB_GATEWAY_PROVIDERS` 时 registry 为 `workbuddy,qclaw,qwenwork,traework,traesolo`。
- **账号接入**：
  - Web 登录闭环：管理页「发起网页登录」→ TRAE 授权页 → 302 回跳 `/authorize`（ExchangeToken + GetUserInfo + 加密入库）；
    支持自定义回调基地址（`CB_TRAESOLO_CALLBACK_BASE` / 请求参数）与手动粘贴回调 URL 兜底。
  - 凭证 JSON 导入：嵌套（`auth`/`account`）与平铺两种结构自动识别；`CB_TRAESOLO_AUTH_DIR` 指定扫描目录（默认不扫目录）。
  - 同 uid 重复导入按更新处理。
- **对话**：OpenAI ↔ SOLO 全量协议转换——`llm_utils_chat` SSE 上游；
  - 非流式：聚合 SSE 为单个 `chat.completion`（content + reasoning_content + tool_calls + usage + finish_reason）；
  - 流式：**真实逐 chunk** 转换为 `chat.completion.chunk`（含 reasoning 增量、tool_calls 增量合并、末尾 usage 与 `[DONE]`）；
  - `tools` / `tool_choice`：OpenAI `function` ↔ SOLO `function_call` 互转，`tool_choice` none/function 归一化；
  - 消息 content 字符串 → 数组形式；`function=solo_work_lite` 固定注入。
- **模型**：动态模型表（`get_detail_param`，1 小时缓存 / 5 分钟失败负缓存，请求路径 best-effort 触发）+
  内置 32 个 `config_name` 静态回退；`auto` → `glm-5.2`；大小写不敏感 + `__dev`/`__max` 后缀剥离。
- **账号冷却状态机**（与 Go 版对齐，多账号自动换号，单请求最多换 3 次）：
  - SSE error / body `code:1005`（plan 权益不足）→ 冷却 12 小时；
  - HTTP 429/404 → 软冷却 60 秒；连续 3 次错误 → 冷却 10 分钟；
  - 401 / token 失效 → 会话死亡：先 refresh 再重试，失败置 `expired`；
  - token 距过期 < 24h 请求前静默预刷新，refresh_token 轮换同步落库。
- **配额**：`ide_user_ent_usage` 各权益包 credits 求和（`GET /admin/accounts/{id}/resources`）。
- **官方签到**：`checkin_credits/status|claim`，对齐现有单账号签到端点（`GET/POST /admin/accounts/{id}/checkin`，
  本版本起非 workbuddy 通道统一分发到各 provider）。
- **Web UI**：账号面板新增 Trae SOLO 登录卡片（发起登录 / 等待 / 取消 / 手动完成）；两个通道的下拉兜底列表补充 `traesolo`。
- **测试**：`tests/test_traesolo.py` 50 个用例（mock HTTP：凭证解析、payload 改写、SSE 聚合/流式、冷却状态机、
  模型映射、登录闭环、换号重试、配额/签到、provider 协议集成）；全量 272 用例通过。
- **真实账号 E2E**（2026-08-27）：登录闭环、流式/非流式对话、tool_calls、动态模型（38 个）、配额（credit 余额）、
  签到（已领判定）、测试对话全部通过，详见 `docs/traesolo-usage.md` 第 9 节。

## 兼容

- 现有 WorkBuddy / QClaw / QwenWork / TraeWork Key 与模型行为不变。
- `glm-5.2` 同时存在于 WorkBuddy 与 Trae SOLO：不带前缀按 Key 绑定通道解析，`traesolo/glm-5.2` 显式指定。
- 收窄通道：`CB_GATEWAY_PROVIDERS=workbuddy`。
- Trae SOLO 与 TraeWork 相互独立（不共享凭据目录、不共享账号）。
