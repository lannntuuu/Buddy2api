# Buddy2api v2.3.0

发布日期：2026-09-28

自 v2.2.0 起的累积发布（113 个提交，280 个文件，+35998 / −7647）。新增 **Qoder CN** 通道、
**配置文件 `config.toml`**、**Trae SOLO 官方模型选择弹窗**与**非对话模型全局过滤**、
**WorkBuddy 频率限制自动换号**、**模型最大输入上下文可配置**；管理台「通道管理 / 模型配置」大幅改版；
用量统计新增「按账号分组」与 t/s 速度列。

> ⚠️ **本版本含破坏性变更**，升级前请先读下一节。最需要注意的是 Trae SOLO 白名单收窄：
> 官方标记不可见的模型（含 `DeepSeek-V4-Pro`）**不再可请求**。

## 破坏性变更

- **Trae SOLO 模型白名单收窄（影响最大）**：新增非对话模型全局过滤，官方 `get_detail_param`
  返回的 42 条里剔掉 `is_invisible_to_user` 为真、`usage` 为 `custom_model`/`summary`、
  名字含 `subagent`/`sub_agent` 或等于 `summary` 的项，只剩 **15 个可见对话模型**。
  被剔除项**不再进入白名单候选，也不再可请求**——如果你的 `traesolo.models` 里配了
  `DeepSeek-V4-Pro`、`DeepSeek-V4-Flash`、`glm-5`、`glm-5-turbo`、`sagitta`、`aquila` 等，
  它们现在会返回 `400 unknown_model`。请在「模型配置 → 刷新官方模型表」弹窗里重选一次。
- **Trae SOLO 静态兜底表 32 → 9 条**：只保留过滤后仍可见的模型，**只删不补**。上游拉不到时的
  兜底范围随之收窄。
- **`/v1/models` 现在列出别名（对外名）而非上游原生 id**：没配别名的 id 仍按原生形式列出，
  所以旧配置不会失效；但若你依赖 `/v1/models` 里的原生 id 做客户端下拉，请改为使用对外名
  （别名才是客户端该发的东西，bind 时会翻回原生 id）。
- **限额存储迁移**：仓库根 `model_limits.json` 废弃，改为全局键进 `gateway_settings.json`、
  通道/模型级进 DB settings。首次读取时**自动一次性迁移**并留下 `model_limits.json.migrated`
  留痕（**不删除**原文件）。示例文件 `model_limits.example.json` 已删除，改为
  `gateway_settings.example.json`。
- **seed 通道可删**：不再按 seed 禁用删除按钮，`bailian` 移出保留 id 名单。删除通道会**真删**
  账号行（含启动时的孤儿清扫）；新建通道**默认启用**。
- **上游 11115（上下文超限）不再换账号**：识别 11115 / `context_length_exceeded` /
  `prompt is too long` / `input length too long`，与 11128 共用「武装 + 精简 + 原地重试」自愈；
  超限失败后**短路账号轮换**，直接透传明确 400（上下文超限换账号无济于事）。

## 新通道

- **Qoder CN（`qodercn`）**：新增通道，opt-in（不在默认通道列表，需 `CB_GATEWAY_PROVIDERS`
  追加或管理页启用）。本机 Qoder CN 登录缓存可导入、查额度、发起对话；协议已冻结
  （`Cosy-Version` 固定，见 `docs/design/multi-channel-v2.md` Appendix A）。
  机器指纹默认读 `%USERPROFILE%\.qoder-cn\.auth\machine_id`，可用 `CB_QODERCN_MACHINE_ID` 覆盖；
  登录目录可用 `CB_QODERCN_AUTH_DIR` 指定。移除 `qoderwork` 占位。
- 默认通道列表**未变**，仍是 `workbuddy, qclaw, qwenwork, traework, traesolo`。

## 配置

- **`config.toml` 配置文件**：启动时自动加载，支持 `[default]` / `[dev]` / `[prod]` profile，
  用 `--config <profile>`（或 `--config <path>`）与 `CB_GATEWAY_CONFIG=<profile>` 切换。
  dev / prod 双 checkout 各自一份（`.gitignore`d，per-deploy 私有）。优先级：
  代码默认 → `[default]` → `[<profile>]` → 环境变量 → CLI。示例见 `config.example.toml`。
- **模型最大输入上下文可配置**：请求链路预检返回 400、`max_tokens` 注入 clamp，
  管理页提供配置界面（「模型配置 → 各平台设置」）。**不引入内置 per-model 上限表**——
  实测各模型真实可达 697k/750k+，硬编码会误杀正常长对话；不配置限额时不预检拦截。
- **TraeWork 会话模式可选**（`work` / `code`）：设置键 `<channel>.mode`，缺失/非法回退
  `work`；`code` 模式联动官方 `solo_agent_lite` 与 `is_in_code_mode` 标记。

## 修复

- **Trae SOLO 官方倍率/展示名大小写不匹配**：官方 `config_name` 是全小写
  （如 `deepseek-v4.1-flash`）而白名单/别名常为混合大小写（如 `DeepSeek-V4.1-Flash`），
  原先的 `model_rate` / `fetch_model_rates` 用大小写敏感查找，导致静默回退到静态值或 `None`。
  现已与 `accepts_model` 对齐为大小写不敏感。
- **WorkBuddy 6004 频率限制**：改为「(账号, 模型)」级记录 + 自动换号 + 全限即停，
  不再一律视为账号故障。
- **TraeWork 自动退出登录**：凭据自愈修复；同时对齐官方 code 模式标记、解析 `token_usage` 真值、
  思考走 `reasoning_content`、转发 system/历史（对齐其它在用通道）。
- **TraeWork 停用后同步任务仍在跑**：停用通道后同步任务不再继续执行。
- **credit 真值优先**：上游回报 credit 真值时优先用真值，不再一律按 token 估算。
- **用量统计同日多账号拆行**：未勾选「按账号分组」时，同通道同模型同日合并为一行，
  派生列由合并后的原始量重算，保证 `Σ 日明细 == 模型小计 == 平台汇总`。
- **缓存命中率口径**：改为百分数，修正少乘 100 的显示错误；命中率 = 命中 ÷ 输入。
- **单字符连击退化护栏**：输出连续 256 个相同字符即中止（流式 `parser_error` / 非流式 502），
  防 hy4 系模型跑飞刷屏烧预算。
- **工具流 502 invalid call id**：空 id 帧视作未携带，EOF 缺 id 合成占位 id（hy4 系上游偶发）。
- **SQLite `database is locked`**：`get_conn` 对有界重试，不再打到热鉴权路径。
- **管理页多处空白/失效**：通道管理空白（`KEY_PANEL_META` 未进 setup return、模板混入 Python
  `not` 关键字）、API Keys 页下拉空白（漏导入 `api`、父级注入函数漏传 prop）、
  详情浮窗「编辑」字段全空、`channel-health` 500（门面未转出）等。

## 管理台

- **通道管理改版**：主从式「通道管理」+「模型配置」独立页；分组列表 + 统一浮窗 + 多 Key 并存；
  详情浮窗化 + 拖拽排序（密钥型组固定在登录型组之后）。
- **自定义 OpenAI 兼容通道**：数据驱动，零代码热生效；`gmi` / `bailian` 迁移为 seed 通道。
- **Trae SOLO 模型选择弹窗**：点「刷新官方模型表」实时拉官方并弹窗，列出可见模型
  （勾选框 + 展示名 + 模型 ID + 官方倍率 + 上下文窗口），白名单已选项预勾选，支持全选/全不选；
  保存只写白名单并清理孤儿别名，思考档位/上下文限额不变；刷新失败不改任何配置。
  `POST /admin/channels/{channel}/models/refresh` 新增 `official_models` 字段
  （完整官方可见列表，不受白名单限制）。
- **WorkBuddy 多账号**：凭证快照固化 + 通道手动锁定（pin）+ 凭证列表通道分组 + 昵称行内编辑。
- **用量统计**：新增「按账号分组」维度（可勾选开关）、t/s 速度列、缓存命中列与计算列公式悬浮；
  分组标题行移到该组内容之上。
- **一键领取**：结果账号列 hover 浮现通道；修复结果表头与列表对不上。
- **API 泄密面收窄**：行对象返回 + 免解密 summary + 批量额度端点。

## 已知问题

- **`gateway_settings.json` 落在 `src/` 而非仓库根**：该文件（全局配置容器，含
  `manual_account_pin` 等）实际路径是 `src/gateway_settings.json`，与 `config.toml`
  不同级——早先的注释写成「与 config.toml 同级」，与实际不符，已修正注释。
  **路径本身保持不动**：prod 现有配置就落在 `src/` 下，改路径会让已存配置静默丢失。
  仓库根若出现同名文件**不会被读取**（旧版本残留，可删）。
- **测试不再受本机 pin 残留影响**：`isolated_db` 原先只隔离 DB、未隔离
  `gateway_settings.json`，本机若手动锁定过账号（pin），调度与限流用例会误红。
  现已一并隔离；同时修掉 `test_rate_limit_failover` 里两个依赖真实时钟的时间炸弹
  （`RATE_BODY` 是 2026-09-21 的 golden 抓包，解除时刻写死）。修复前 4 failed /
  808 passed，修复后 0 failed / 812 passed。
